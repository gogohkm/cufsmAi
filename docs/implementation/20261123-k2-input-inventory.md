## 1. 어떻게 만들었고, 빠짐없음을 어떻게 보았나

목록은 코드에서 만든다. 손으로 적은 것은 MCP 대응표 · 의존 설명 · 함수 → 메시지 표 셋이고, 그것도 자동으로 대조한다.

| 칸 | 어디서 |
|---|---|
| 칸 · 탭 · 묶음 · 표지 · 처음 값(SI · US) · 선택지 · 읽기 전용 · 처음 숨김 | 진짜 웹뷰를 헤드리스 Edge 에 띄워(진짜 호스트 · 파이썬) DOM 을 문서 차례로 걸었다 — `run.js` 의 `defaults` 묶음 → `test/rendered/out/k2/dom_controls.json`. US 값은 단위 단추를 눌러 다시 읽었다 |
| `.csd` 키 · 단위 종류 · 보기 전용 | `webview/js/designState.js` 의 `FIELDS` · `VIEW_ONLY_CONTROLS` (require 로 읽음) |
| 읽는 곳 · 이어지는 메시지 · 본문 키 | `webview/js/app.js` 에서 그 id 를 글자로 쓴 줄을 모두 찾아, 그 줄을 품은 맨 위 함수 · 처리기(단추 처리기는 `const btnX = …` 부터 닫는 줄까지)로 묶고, 함수 → 메시지 표로 잇는다. 본문 키는 `key: reqNum('id'…)` · `_optNum` · `zeroNum` · `_optPos` · `['key', 'id']` 꼴을 정규식으로 |
| 처음 값의 출처 | `src/webview/StcfsdPanel.ts` 의 그 칸 줄(`${steelFy}` 같은 치환이면 강종 표), app.js `_syncAnalysisWidgetsFromModel` · `renderPreprocessor` 가 쓰는 칸(호스트 모델), 거울 표 |
| MCP 인자 | 진짜 MCP 서버(`src/mcp/*.ts` 를 transpile)의 `tools/list` 스키마. 대응표의 인자가 스키마에 없으면 생성이 실패한다(지금 0) |
| MCP 가 화면 칸에 닿는가 | 렌더 시험이 MCP 도구를 진짜로 부르기 전 · 뒤에 모든 칸을 읽어 비교한 것(`golden/mcp-*.json` 의 `inputsChanged`) — 코드 읽기가 아니라 관찰 |

빠짐없음:

- `test/webview/k2_inventory_contract.js` 가 **`StcfsdPanel.ts` 의 HTML 에서 정규식으로 뽑은 121개 id 와 `app.js` 가 만드는 경간 표 4종이 모두 목록에 있는지**, `designState.FIELDS` 119 키가 같은 `.csd` 키 · 단위로 있는지, 목록 수가 화면 칸 수와 같은지 본다. 새 칸이 생기면 실패한다.
- 걸은 DOM(125) = HTML 정규식(121) + 경간 표(4). FIELDS 에 있는데 화면에 없는 키 0, 화면에 있는데 FIELDS 에 없는 칸 2(`select-length` · `select-mode` — 보기).
- 렌더 시험은 FIELDS 의 **모든 키**를 처음 값과 다른 값으로 넣은 `.csd` 를 만든다(`test/rendered/k2/values.js` — 키가 빠지거나 값이 처음 값과 같으면 시험이 실패). 그래서 새 입력이 저장 · 복원에서 빠지면 왕복 시험이 잡는다.
- 화면 밖에서만 받는 입력(MCP 에만 있는 설계 인자)은 JSON 의 `mcpOnlyDesignArgs` 에 도구별로 모았다 — K2 상태가 함께 가져야 할 것의 후보(설계 문서 2.4절).

## 3. 손으로 정한 공학 기본값 ⚑ (39)

화면 HTML 의 `value` · `checked` · 고른 선택지, 또는 화면 JS 가 적는 값. 사람이 아무것도 하지 않으면 이 값으로 계산이 돈다. 엔진 리뷰의 「조용한 기본값」 원칙(빈 칸을 지어내지 않는다)은 **빈 칸**에 대한 것이었고, 처음부터 칸에 적힌 이 값들은 그대로 남아 있다.

| 무엇 | 값 (SI 화면 / US 내부) |
|---|---|
| 부재 · 경간 | 부재 유형 **지붕 퍼린(자동 계산)**, 경간 유형 3연속(cont-3), cont-n 의 경간 수 5, 간격 1.0 m, 경간 길이 5 m(JS `buildSpanTable`), 지점 P(핀) |
| 하중 | D 0.3 · Lr 1.0 · S 0.5 · Wu 1.0 kPa, **활하중 패턴 재하 켬** |
| 데크 | 판 두께 0.5 mm, 체결 간격 300 mm |
| 설계 | **설계법 LRFD**, Cb(−) · Cb(+) 1.0, Cmx · Cmy 1.00, **β 보정 켬**(M1/M2 0 · Lm 0). 2026-11-25 부터 KxLx · KyLy · KtLt · Lb(−) 는 빈 칸(전에는 3000 mm), §A3.3.2 냉간가공은 끔(전에는 켬) |
| 웹 크리플링 | N 89 mm, R 4.8 mm, 지점 EOF, 체결됨, 단일 웨브, 보강 플랜지, 웨브 수 1 |
| 랩 | 왼쪽 · 오른쪽 랩 305 mm, 나사, 지름 4.8 mm, 행 2 |
| 단일 접합 | 나사, t1 · t2 1.5 mm, d 4.8 mm, n 4, 용접 길이 50 mm · 크기 3 mm, 완전용입 |

눈여겨볼 것:

- **냉간가공(§A3.3.2)은 처음에 꺼져 있다**(2026-11-25 — 전에는 켜져 있어 모든 직접 입력 설계와 퍼린 설계가 `use_cold_work: true` 를 보냈다. 강도를 올리는 선택이라 누가 켰을 때만).
- **유효 길이 · 비지지 길이는 처음에 빈 칸이다**(2026-11-25 — 전에는 3000 mm). 사례마다 다른 값이다. 비면 요청에 넣지 않고, 엔진은 그 길이가 필요한 E2 · F2 를 「평가하지 못함」 으로 낸다(판정 없음). 퍼린 길은 하중 해석의 구간 길이를 쓰므로 닿지 않는다.
- 직접 입력 모드로 바꾸면 β 보정 체크가 꺼진다(V4-17 — 처음 모드가 자동 계산이기 때문). 그래서 「β 켬」 은 자동 계산 모드에서만 처음 값이다.
- 강종을 고르면 화면 JS 가 **E 29500 · G 11300 ksi** 를 칸에 적는다(`app.js` 의 강종 처리기) — 결함 D-8.
- 해석 칸의 HTML 값(반파장 10 – 10000 mm · 60개)은 쓰이지 않는다 — 화면이 뜨자마자 호스트 모델(1 – 1000 in · 50개)이 덮는다.

## 4. MCP — 인자는 있는데 화면에 오지 않는다

- 도구 인자로 칸을 정할 수 있는 것은 114 개다. **그러나 MCP 로 정한 값이 남는 곳은 호스트 모델뿐**이고(16 칸이 그 길로 화면에 온다), 설계 · 하중 · 접합 도구의 인자는 그 계산 한 번에만 쓰이고 사라진다. 결과는 화면에 온다(`designResult` · `designPurlinResult` · `connectionResult` · `lapConnectionResult`) — 그래서 **화면은 MCP 결과 옆에 다른 입력을 보인다**.
- `analyze_loads` 는 결과도 화면에 보내지 않는다(K4 의 몫).
- MCP 에만 있는 설계 인자(화면 칸이 없음): 휨 `cantilever` · `moment_sign` · `shear_n_webs` · `transverse_stiffeners` · `kphi` · `Fcre` · `wc_M` · `wc_section_type`, 조합 `transverse_load` · `L`, 인장 `An`, 퍼린 · 하중 `section{…}` · `E` · `deck.Fss_kip` 등 데크 체결 상세 · `loads.R` · `deck.R_tested_gravity`, 랩 `Se` · `Sf` · `Mnd` · `Vn` · `Fub` · `bolt_grade` · `hole_type` …, 단일 접합 77개(J 장의 세부 인자). 전체는 JSON 의 `mcpOnlyDesignArgs`.
- 단위: 화면의 하중은 면압(psf · kPa)이고 MCP 는 선하중(plf — `loads.D` = psf × 간격). 화면의 경간 · 간격 · 브레이스는 ft(SI 는 m), 나머지 길이는 in(mm).

## 5. 파생 · 거울 · 의존

- **하중 해석이 채우는 칸** 18: `design-Mx` · `design-Mx-pos` · `design-V` · `design-wc-P` · `design-wc-support` · `design-Lb` · `design-Cb` · `chk-beta-dist` · `design-dist-M1M2` · `design-dist-Lm` · `chk-r-factor` · `select-r-value` · `design-Lb-pos` · `design-Cb-pos`(`renderLoadAnalysisResult`), `conn-lap-left` · `conn-lap-right` · `conn-Mu` · `conn-Vu`(`_autoFillLapInputs`). 사용자가 넣는 칸이기도 하다 — 출처가 섞인다. `.csd` 를 열 때 호스트는 하중 해석 결과를 보낸 뒤 입력을 한 번 더 보내 사용자 값을 다시 얹는다.
- **거울**: ① Fy → ③ 설계 Fy(읽기 전용) · 소성 fy · 접합 Fy, ① Fu → ③ 설계 Fu · 접합 Fu. 소성 fy 를 고치면 거꾸로 ① 로. 파일을 열 때는 저장된 `fy` 가 이긴다(`fyLoad` · `plasticFy` 의 다른 값은 버림 — 고정값 `csd-roundtrip` `coupled.*`).
- **켜기 · 보이기**: 부재 유형(행 보이기, 자동 → 직접으로 바꾸면 파생 칸 5개를 비우고 β 를 끔), 경간 유형 · 경간 수(표를 다시 만든다), 접합 유형(보내는 인자 자체가 달라짐), 하중 경우(custom 칸), 템플릿(립각 칸), β 체크(β 칸), R 체크(R 값 · 경간 조건), E · ν → G. 각 줄의 근거 줄 번호는 JSON 의 `drives`.
- **결과 무효화**: ② 탭의 모든 칸 → 하중 · 설계 · 랩 · 보고서 · 검증(`load`), ③ · ① 탭의 칸(보기 전용 18개 제외) → 설계 · 랩 · 보고서 · 검증(`design`), 해석 조건 9칸은 「해석 실행」 때 호스트가 해석을 무효화. **④ 접합부 탭은 아무것도 무효화하지 않는다**(결함 D-4).
