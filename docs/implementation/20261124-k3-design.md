## 0. 결론

- 지금 검증(「설계 검증 실행」)과 상세 보고서(「상세 보고서 생성」 · 「PDF 저장」)는 **웹뷰 JS 안에서만** 만들어진다. 입력은 화면의 칸(DOM)과 웹뷰가 쥔 결과의 사본이다. MCP `validate_design` 은 `checks: []` 와 원자료, `generate_report` 는 JSON 묶음을 돌려준다 — 화면과 다르고, 웹뷰가 없으면 검증도 계산서도 없다.
- **권장: 호스트가 계산하고 화면은 보이기만 한다.** 검증 · 보고서는 순수 모듈 하나(`webview/js/review.js`, `designState.js` 처럼 UMD — 호스트가 `require`, 시험이 그대로 부른다)에 둔다. 입력은 호스트가 이미 쥔 것: 검토 상태(`CaseState`, K2), 모델, 해석 · DSM · 하중 해석 · 설계 · 랩 · 접합 결과(엔진의 `design_checks` 포함). 보고서는 **자료 먼저**(`ReportDoc` — 절 · 표 · 식 · 그림 자료, US 값 + `quantity`), **그리기 둘째**(`renderReportHtml(doc, units)`) — 웹뷰 · 새 화면 · PDF 가 같은 자료를 그린다.
- PDF 는 웹뷰가 필요 없다: 호스트가 HTML 을 만들고 지금의 길(시스템 Edge headless `--print-to-pdf`, `windowsHide`)로 인쇄한다. 확장 · 독립 프로그램 모두 같다. Electron 의 `printToPDF` 는 나중에 꽂을 자리(「PDF 인쇄기」 갈고리)만 둔다.
- 단계는 K2 처럼: **먼저 옮기고(값 · 글 · HTML 이 바이트까지 같게), 그다음 고친다.** 옮기는 동안 시험 모드에서 화면이 만든 것과 호스트가 만든 것을 맞댄다(그림자).
- 고정하며 찾은 결함 18(부록 A). 크게: 판정 없음인 엔진 항목을 「통과」 로(D1), 냉간가공 「실패」 가 거의 모든 휨 검토에(D2), 퍼린 묶음에서 「해석 미실행 · DSM 미추출」 실패(D3), 늘 통과인 항목 5(D6), 보고서의 상수 E 29500 · ν 0.30(D8), SI 보고서의 US 단위(D10), MCP 요약 응답 42 KB(D18).

## 2. 어디에 두나 — 권장: 호스트가 계산, 화면은 보기만

| | A. 공용 순수 모듈을 호스트 · 화면이 같이 돌린다 | **B. 호스트만 돌린다(모듈은 UMD — 화면은 결과를 받아 그린다)** |
|---|---|---|
| 같은 판정 | 입력을 둘이 따로 모은다 — 화면은 DOM, 호스트는 상태. K2 이후 같아야 하지만 둘이다 | 한 곳. 화면 · MCP · 새 화면 · PDF 가 같은 항목 |
| 웹뷰 없이 | 된다(호스트 쪽) | 된다 |
| 화면 반응 | 누르면 바로 | 메시지 한 번(수 ms — 엔진을 부르지 않는다) |
| 시험 | 둘 다 시험해야 | 하나. 옮기는 동안만 그림자(화면이 옛 코드로 만든 것 = 호스트가 만든 것) |
| 무게 | `app.js` 에 남는다 | `app.js` 에서 약 1,900줄이 빠진다(검증 940 · 보고서 950) |

**B 를 권한다.** 판정이 화면과 MCP 에서 같아야 한다는 것이 K3 의 뜻이다. 모듈을 UMD 로 두는 까닭은 둘: 호스트(Node)가 그대로 `require` 하고(`designState.js` · `utils.js` 와 같은 길 — `out/` 빌드가 필요 없다), 옮기는 동안 화면이 같은 모듈을 불러 그림자 대조를 할 수 있다. 옮긴 뒤 화면은 모듈의 그리기 함수(`renderValidationHtml` · `renderReportHtml`)만 쓴다 — 그것도 호스트가 HTML 을 보내면 필요 없다(결정 1).

입력 하나(`ValidationInput`) — 호스트가 만든다:

## 4. 보고서 — 자료 먼저, 그리기 둘째

`ReportDoc`(JSON, 엄격 — NaN 없음):

```jsonc
{ "schema": "stcfsd-report/1", "kind": "design" | "buckling",
  "meta": { "title", "spec": "AISI S100-16", "method", "caseRev", "file", "created": "ISO" },
  "sections": [ { "id": "section", "title": "단면", "blocks": [
      { "type": "table", "columns": ["항목","값","단위"], "rows": [ { "label": "H (높이)", "value": { "value": 8, "quantity": "length" } } ] },
      { "type": "equation", "text": "My = Sf × Fy", "result": { "symbol": "My", "value": 106.64, "quantity": "moment" }, "source": { "kind": "design_check", "id": "member.flexure.global", "step": 1 } },
      { "type": "figure", "figure": { "kind": "signature_curve" | "section" | "beam" | "diagram", "data": { … } } },
      { "type": "verdict", "state": "PASS" | "FAIL" | "NOT_CHECKED", "label" },
      { "type": "notes", "kind": "warnings" | "assumptions" | "scope_notes" | "not_evaluated", "items": [ … ] } ] } ] }
```

- **값은 US + `quantity`**(검토 항목 계약과 같은 어휘). 그리기가 단위를 붙인다 — SI 보고서에 `ksi` 가 새지 않는다(D10). 끝없는 값은 `{value: null, unbounded: true}` → '∞'(D5).
- **숫자는 엔진 · 상태 · 모델에서만.** 지금 화면이 스스로 만드는 수(목록 「보고서」 표 — 13: 상수 E · ν, 선하중 = 면압 × 간격, 감소율, 2.78Fy · 0.56Fy, 상수 φ / Ω, Mu = 비 × 강도, 빈 칸에 기본값, 칸의 글 그대로의 Lb · Cb · 단면 치수)는 옮기는 단계에서는 같게 두고(바이트 대조) 고치는 단계에서 원천으로 바꾼다.
- **설계 계산 절은 `design_checks` 에서.** 지금 보고서는 휨이면 「단계 1 – 5」 의 설명 글을 화면이 지어 쓰고 값만 결과에서 가져온다. 계약은 항목마다 조항 · 식 · 단계(입력 · 결과 · 출처)를 준다 — 보고서는 항목마다 「소요 · 공칭 · 계수 · 설계강도 · 비 · 판정」 표와 단계 식(`expr` + 입력을 대입한 줄)을 그린다(Manual 예제처럼 모드마다). 이것은 K3 의 뒤쪽 단계(K3-7)다 — 앞 단계에서는 지금 보고서를 그대로 자료로 옮긴다.
- 그리기: `renderReportHtml(doc, {units})`(웹뷰 · PDF 같은 HTML — 지금의 인쇄용 CSS 그대로), 새 화면은 자료를 직접. 그림은 SVG 를 그리기가 만든다(지금 `renderDiagramSVG` · `renderBeamSchematic` · 보고서의 서명곡선은 이미 SVG — 옮긴다). 좌굴 보고서의 캔버스 그림(모드 형상 2D · 3D · 분류 · 소성 곡면)은 화면에서만 나온다 — 화면이 있으면 그 PNG 를 붙이고, 없으면 서명곡선 SVG 만(결정 5).

**두 보고서와 하나 더:** 상세 보고서(설계 · 하중) · 좌굴해석 결과 보고서 · 엔진의 글 보고서(`report`, 클립보드). 셋째는 엔진 것이라 K3 에서 바꾸지 않는다.

## 5. PDF — 웹뷰 없이

- 확장: 호스트가 `renderReportHtml` 로 HTML 을 만들고 지금의 `_saveReportPdf` 길로(대화상자 → 임시 HTML → 시스템 Edge headless). 화면의 「PDF 저장」 은 `saveReportPdf {html}` 대신 `saveReport {format}` — HTML 을 화면이 만들지 않는다.
- 독립 프로그램: 같은 호스트 코드가 Node 에서 돈다(`desktop/host`) — 같은 길. `desktop/shell/README.md` 의 판단(직원 PC 에 Edge 가 있다)과 같다. Electron 인쇄는 호스트에 「PDF 인쇄기」 주입점(`setPdfPrinter((html, file) => Promise)`)을 두고 기본은 Edge — 독립 프로그램이 원하면 꽂는다(결정 5).
- MCP: 대화상자가 없다 — 정해진 자리에 쓴다(결정 7).
- Edge 가 없으면 지금처럼 HTML 로(경고와 함께) — MCP 응답에도 그 사실.

## 6. MCP

| 도구 | 지금 | K3 뒤(요약이 기본 · `detail` · 12 KB) |
|---|---|---|
| `validate_design` | `checks: []` + 원자료(단면 성질 · cutwp · DSM · 하중 해석 · 설계 결과 통째). 요약 3 – 42 KB, full 3 KB – **2.9 MB**(퍼린) | 요약: `counts {pass, warn, fail}` · `pass` 가 아닌 항목 `[{id, category, item, status, value, note, source?}]` · `case_rev` · 단위. `detail: 'all'` 이면 모든 항목. 원자료는 싣지 않는다(다른 도구에 있다 — `get_section_properties` · `get_dsm_values` · `get_design_check`). 화면과 같은 항목(같은 모듈) |
| `generate_report` | JSON 묶음(+ `member_type` 을 주면 설계를 다시 돌림). 요약 3 – 42 KB | 보고서를 **만들어 파일로**(HTML · PDF): `{file, pdf_file?, pages?, sections: [title], verdict, not_evaluated?, case_rev}`. 요약에 자료를 싣지 않는다. `detail: 'doc'` 이면 `ReportDoc`(12 KB 를 넘으면 절 목록과 `more`). 설계를 다시 돌리는 인자(`member_type` · `Fy` …)는 지운다 — 그것은 `run_case_check` 의 일(K2) |

두 도구 모두 `units`(SI 면 항목 값 · 표 값을 `quantity` 로 — `siUnits`). `mcp_si_chain` 의 예산 시험에 넣는다(요약 ≤ 12 KB, 퍼린 38 구간 사례 포함). 안내문의 흐름(… → 부재 검토 → 접합부 → **검증 → 계산서**)에 두 도구의 자리.

## 7. `.csd`

**새로 저장하는 것 없음(권장).** 검증과 보고서는 상태 · 결과에서 다시 만든다(판정이 결과의 함수). 결과는 이미 서명과 함께 저장된다(`designResult` · `lapResult` …). 보고서 파일을 만든 기록(언제 · 어느 판 · 어디)은 R5(발행)의 몫이다. 단, `ReportDoc.meta.caseRev` 를 남겨 「보고서 이후 바뀐 것」 을 셀 수 있게 한다(새 화면의 진행 띠 — 구성안 3.3).
