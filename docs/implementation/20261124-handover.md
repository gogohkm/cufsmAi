## 2. 새 PC 에서 시작하기

### 2.1 필요한 것

- Windows, Git, **Node 22**(이 PC 는 v22.20.0 · npm 11.7.0), **Python 3.13**(이 PC 는 3.13.14)
- Microsoft Edge 또는 Chrome — 화면을 띄우는 시험이 화면 없이(headless) 쓴다. 다른 자리에 있으면 환경 변수 `V4_BROWSER` 로 준다
- 설치 파일을 만들 때만: 인터넷(처음 한 번 Python 과 휠을 받는다)

### 2.2 받아서 준비하기

```powershell
git clone https://github.com/gogohkm/cufsmAi.git C:\Coding_Works\cufsmAi
cd C:\Coding_Works\cufsmAi

# 파이썬 — 저장소 루트의 .venv 를 호스트가 가장 먼저 찾는다
py -3.13 -m venv .venv
.venv\Scripts\python.exe -m pip install numpy==2.4.4 scipy==1.17.1 pytest ruff

# 확장 호스트 · 웹뷰 · MCP 서버
npm install
npm run build              # out/ · 웹뷰 번들 · media/mcp-server.js

# 독립 프로그램
cd desktop;  npm install;  npm run build
cd shell;    npm install
cd ..\..
```

- numpy · scipy 는 **이 PC 와 같은 판**을 쓴다(설치 파일에 묶는 판이기도 하다). 판이 다르면 좌굴 값의 끝자리가 달라질 수 있다.
- 같은 경로(`C:\Coding_Works\cufsmAi`)에 받으면 Claude Code 의 프로젝트 기억 폴더 이름이 같아진다(7절).
- `npm ci` 가 실패하면 `npm install` 을 쓴다(루트의 lockfile 이 `package.json` 과 어긋난 적이 있다 — 작업문서 8.1절 5b).

### 2.3 준비가 됐는지 보기 (5분)

```powershell
npm run test:quick                                   # 형 검사 · 린트 · 도구 대조 · 계약 몇 개 — 약 20초
.venv\Scripts\python.exe test\python\run_all.py      # 엔진 483 — 몇 분
npm run test:records                                 # 기록 142 — 약 10초
```

셋이 통과하면 환경은 됐다. 화면을 띄우는 긴 시험(`test:rendered` · `test:k2` · `test:k3`)은 그 대상을 고칠 때만 돌린다(5절의 규칙).

**새 PC 에서 고정값 불일치가 나오면 다시 받아들이지 말고 먼저 원인을 본다.** 같은 PC 에서는 결과가 바이트까지 같지만 PC 사이에서는 끝자리가 다를 수 있다 — 국부 · 뒤틀림 좌굴은 상대 1e-9, 긴 반파장의 전체 좌굴은 1e-5 까지(엔진 계약 [`20261123-check-contract.md`](20261123-check-contract.md) 15절). K2 는 수를 1e-9 로 견준다.

### 2.4 프로그램을 띄워 보기

```powershell
cd desktop
npm run serve -- --open <파일.csd>        # 브라우저로 — 출력된 「화면:」 주소를 연다(개발용)
cd shell;  npm start -- <파일.csd>        # 창(Electron)
```

자세한 것은 [`desktop/README.md`](../../desktop/README.md).

### 2.5 Claude Code 로 이어 갈 때 첫 말

> `docs/implementation/20261124-handover.md` 와 작업문서를 읽고, 인수인계 문서 4절의 남은 일을 순서대로 이어서 진행해줘. 오케스트레이터로서 Opus 5.5 서브에이전트에게 맡기고, 작업이 끝날 때마다 작업문서를 고쳐줘. 5절의 규칙을 지켜줘.

이 PC 의 세션 기록과 에이전트는 옮겨지지 않는다. 새 세션은 이 문서와 작업문서만 보고 시작한다.

## 5. 일하는 규칙

사용자가 정한 것과 작업하며 굳어진 것. 새 세션에도 그대로 적용한다.

**진행**

- 오케스트레이터가 **Opus 5.5 서브에이전트**에게 단계별로 맡긴다. 같은 파일을 두 에이전트가 고치지 않는다(엔진 `python/` · 호스트 `src/` `webview/` · 화면 `desktop/` 으로 나눈다).
- **작업이 끝날 때마다 작업문서를 고친다.**
- 커밋은 단계마다, 메시지는 한글. **푸시는 사용자가 말할 때만.**
- 사용자가 위임한 결정은 오케스트레이터가 정하고 작업문서에 「사용자가 볼 것」 으로 남긴다.

**시험** — 꼭 필요한 것만

- 바뀐 곳에 닿는 시험만 돌린다. 에이전트가 돌린 것을 오케스트레이터가 통째로 다시 돌리지 않는다(증명이 되는 한두 개만).
- 긴 묶음(`test:rendered` · `test:k2` · `test:k3` · 새 화면 전체)은 그 대상이 바뀔 때만. 전체 실행과 독립 검증은 마일스톤에서만.
- 다만 **호스트가 화면의 편집을 다루는 규칙을 고치면 `test:rendered` 와 `test:k2` 를 돌린다** — 지금의 화면이 실제로 무엇을 보내는지 아는 곳은 거기뿐이다. `test:quick` 은 계약 시험 전부를 돌리지 않으므로 호스트를 넓게 고친 커밋 앞에는 `test:webview` 전체를 돌린다.
- 고정값(golden)은 까닭을 적을 수 있을 때만 다시 받아들인다.
- 「혼자 돌리면 통과한다」 는 원인이 아니다. 원인을 찾기 전에는 타이밍 탓으로 적지 않는다(그렇게 적었던 셋이 모두 제품의 결함이었다).

**하지 않는 것**

- **이 PC 에 설치 파일을 실행하지 않는다.** 레지스트리 · 시작 메뉴 · 파일 연결을 쓰지 않는다. 시험은 `%APPDATA%\StCFSD` 와 진짜 문서 폴더를 건드리지 않는다.
- 사용자의 진짜 MCP 설정 · Claude Desktop 설정 파일을 쓰지 않는다. 저장소의 `.mcp.json` · `Example/.mcp.json` · `Example/.claude/mcp.json` · `.claude/` 의 로컬 변경은 커밋하지 않는다.
- 시험은 창을 보이지 않고, 포커스를 가져가지 않고, 프로세스를 남기지 않는다. 에이전트는 자기가 띄운 프로세스만(PID 로) 끈다.
- `C:\Coding_Works\StAnal` 은 읽기만 한다(브랜치를 바꾸거나 고치지 않는다).
- `desktop/` 에 엔진이나 설계 로직을 복사해 오지 않는다. 계산은 한 벌이다(`desktop/README.md` 의 규칙).

**판정의 뜻** — 되풀이된 결함의 꼴

- 불합격 > 미검토 > 통과. 「주지 않음」 은 0 이 아니고, 0 은 「해당 없음」 이 아니고, 「해당 없음」 은 통과가 아니다.
- 사람과 AI 는 한글을, 화면이 고른 단위로 읽는다.
