## 4. 단계별 기록

### H — 호스트(끝)

**N-3(E1–E3).** `_caseRunCheck` 가 부재 검토 앞에 `_caseEnsureDesignDsm` 을 부른다 — 설계용 좌굴값이 지금 것이 아니고(없음 · 서명이 다름 · 필요한 계열이 없음) 이 대상에 FSM 좌굴값이 있었으면(준비된 값 · 해석 결과가 있거나 장부에 `design_dsm` · `buckling_analysis` 가 있다) `prepare_design_dsm` 과 같은 것을 돌린다(본문의 설계 Fy). 계열: 압축 P, 조합 P + Mxx, 휨 · 자동 계산 넷 Mxx, 인장 없음. 준비가 실패해도 검토는 돌고 답이 까닭을 적는다. 답의 `case_check.buckling_values {source, load_cases?, by_family?, note}` — `source` 는 `fsm-prepared-now` · `fsm-current` · `fsm-in-check`(퍼린 사슬 — 자기 서명곡선을 푼다) · `mixed` · `analytical` · `not-needed`. `prepare_design_dsm` 은 지금 것이 있으면 `reused: true` 로 그대로 돌려준다(다시 풀지 않고 실행 줄도 없다). 열 때의 안내는 한 문장(`RERUN_GUIDE`)으로 — `run_case_check` 가 부재 검토와 그것이 쓰는 FSM 좌굴값을, 좌굴 해석의 보기는 `run_analysis` 가 되살린다. `load_project`(AI 의 열기)도 화면의 열기처럼 장부를 비우고 되살리지 않은 결과를 장부에 적는다 — 그래야 그 길로 연 뒤에도 「FSM 이 있었다」 를 안다(지시 밖에서 더한 것).

**4.7(E7 · E8).** `new_case` — `from` 이 없으면 프로그램의 처음 모델(`_initialModel` — 새 패널이 시작하는 것의 사본, 없으면 같은 길로 만든다) + 처음 입력, `from:'current'` 면 지금 모델 + 지금 입력. 부재 종류가 부재 유형이면 두 길 모두 `memberType = kind`. 답의 `from` 은 `'current' | 'initial'`, `contents` 에 무엇이 들었는지. 화면의 「새 검토」 는 처음 모델, 「프로젝트로 만들기」 는 지금 것 그대로. .csd 의 맨 위에 `referenceStress {source:'ai', loadFy}` — 저장 · `new_case from:'current'` 가 쓰고, 두 열기 길이 그 `loadFy` 가 모델의 것과 같을 때만 되살린다. 되살렸으면 「선택이 파일에 없다」 는 알림을 내지 않는다(표지가 없는 옛 파일에는 그대로). 결과 봉인 밖의 칸이다.

**N-4.** 끼운 화면이 `resultsCleared` 를 받으면 상태 줄과 설계 탭 띠를 비운다.

**N-7.** (a) 원인: 끼운 화면에서 칸의 `change` 가 탭의 처리기(→ `invalidateDerivedResults`)에 먼저, 문서의 처리기(→ `caseEdit`)에 나중에 닿는다. `invalidateDerivedResults` 가 묶음을 여는 명령(`PAGE_EDIT_COMMANDS`)에 없어 장부의 줄이 묶음이 열리기 전에 적혔다 — 그 명령을 넣었다. 또 `noteRun` · `markVia` 가 문맥을 펼쳐 다시 만들면서 숨은 표지(`__t0`)를 떨어뜨렸다 — `extendCtx` 로 잇는다. (b) 두 열기 길이 `_noteOpener` 로 연 쪽을 적는다(AI → ai, 화면 → person) — 앞 대상의 행위자를 잇지 않는다. `run_case_check` 안의 준비는 그것을 부른 쪽(`_dsmCause`). (c) `formatNumber` 가 정수부 4 자리부터 쉼표(소수부 · 지수 꼴 · 쉼표로 잇는 짧은 수 목록은 그대로). 구조 값 `from` · `to` 는 수 그대로.

**시험.** 새 `test/webview/retest_fixes_contract.js`(N-3 버림 → 다시 계산이 FSM 값 · 그 실행의 행위자, FSM 없던 대상은 해석식 + 안내, E2 · E3 · E7 · E8 왕복 · 옛 파일, N-7a–c), `records_changes.js` 에 E10. `test/records/run.js` 전부, 호스트 계약 시험 17개, `build:mcp` · 도구 맞대기, 고정값(`k2 --only=gui,mcp,reload` 11단계 불일치 0) 통과. 고친 기대값 없음.

### U — 화면(끝)

**N-1(E6).** `changes.ts` 의 `timeline()` — 보이는 실행 하나에 머리줄 하나(자동 실행 · `design_dsm` 은 머리줄이 아니다). 실행이 실린 묶음(`runs`)은 그 가운데 **첫** 실행 아래(호스트 `_workTimeline` 이 `work_log` 에 쓰는 연결 — 앞에는 가장 늦은 것이었다), 그 실행이 머리줄이 아니면 그 뒤의 첫 머리줄. 시각으로 놓이는 묶음은 그 뒤의 첫 머리줄(같은 때면 실행이 먼저 — 호스트와 같다). 묶음이 없는 실행은 「계산 #n (입력 변경 없음)」 한 줄(판정은 보인다). 처음 펼치는 것은 묶음이 있는 최신 머리줄 셋. 판정 변화는 묶음의 실행 가운데 판정비가 있는 첫 것으로.

**N-3 의 화면 몫(E4 · E5).** [다시 계산] 은 버린 것을 차례로 — 좌굴 해석(`run_analysis`, 버렸으면) → 부재 검토(`run_case_check member`, 늘) → 랩 · 단일 접합(버렸으면). 한 단계가 안 되어도 나머지를 하고, 한 것 · 못 한 것과 호스트가 밝힌 좌굴값의 출처를 알림에 적는다. 다 됐을 때만 띠를 닫는다. 부재 검토가 FSM 이 아닌 좌굴값으로 계산됐으면(`dsm_basis_by_family` 의 어느 계열이 `none`) 「해석식 좌굴값」 표시 — 결과 › 부재 검토 · 업무 › 점검 › 판정 요약 · 정보 창의 「좌굴 값의 출처」. 그 키가 없는 결과(인장 · 퍼린 · 옛 결과)와 원형관(고지 `member.scope.round_tube_dsm_not_applicable`)에는 달지 않는다. 조합 부재의 겹친 `dsm_source` 가 `[object Object]` 로 찍히던 것도 고쳤다.

**N-5(E11).** `titlebar.ts` 의 `fitTitle()` 이 넘침을 재어 단계로 줄인다 — 짧은 이름 → 점만(이름은 풍선에) → 「검토 대상」 숨김 · 파일 이름 줄임. 800 px 에서 점만, 900 – 1100 px 짧은 이름, 1440 px 부터 온 이름. 진행 띠의 자리는 넘치면 잘린다(단추 위로 그리지 않는다). 화면의 최소 너비 900 → 780 px(800 px 에서 가로 스크롤 없음).

**시험.** `ui.mjs` 에 u10n(800 – 1440 px 일곱 너비: 진행 띠 · 칩과 단추 · 연결 상태의 상자가 겹치지 않는다 · 가로 스크롤 없음), r43(FSM 없던 대상의 표시 — 해석 뒤 다시 계산하면 사라진다), r44(머리줄 수 = 보이는 실행 수 · 두 번 다시 계산해도 묶음이 그 계산 아래 · 트리의 연결 = 호스트 `work_log`), r45(프로젝트 대상의 좁은 제목 표시줄). 고친 기대값: r42(실행이 실린 묶음은 **첫** 실행 — E6), u5f(차례가 「좌굴 해석 → 부재 검토」 · FSM 값으로 돌아온다).
