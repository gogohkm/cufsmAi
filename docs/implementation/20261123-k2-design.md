## 0. 결론

1. **호스트가 검토 상태(`CaseState`)를 갖는다.** 지금 `.csd` 의 `designInputs` 와 같은 키 · 같은 US 단위의 평평한 표다(`designState.FIELDS` 119 키 + 경간 표 3 배열). 표는 지금처럼 `webview/js/designState.js` 하나 — 화면과 호스트가 같은 파일을 읽는다. 새 모양을 만들지 않으므로 1.0 – 1.3 파일의 이전이 「같은 표로 읽기」 하나로 끝난다.
2. **해석 조건 19칸(템플릿 · 치수 · E · ν · G · 경계조건 · 반파장 · 고유치 수 · 하중 경우 · custom P/M)은 지금처럼 호스트 모델이 주인이다.** 상태에 두 벌로 두지 않는다. 지금도 이 칸들만은 MCP 가 바꾸면 화면에 온다(고정값 `mcp-analysis`).
3. **화면은 지우지 않고 편집기로 바꾼다.** `app.js` 를 한 번에 다시 쓰지 않는다. `designState.js` 에 작은 어댑터를 더해 ① 칸이 바뀌면(사람이든 화면 JS 의 거울 · 자동 채움이든) 표 전체를 읽어 바뀐 키만 호스트로 보내고(`caseEdit`) ② 호스트가 보낸 상태를 칸에 얹는다(`caseState` — 지금의 `restoreDesignInputs` 와 같은 길).
4. **실행 단추는 한 묶음씩 호스트의 상태로 돈다.** 먼저 「그림자」로 — 호스트가 상태로 만든 엔진 요청이 화면이 만든 것과 **바이트까지 같은지** 시험으로 본 뒤에 바꾼다. 고정한 엔진 요청 315건이 그 잣대다.
5. **MCP 의 설계 도구는 받은 인자를 상태에 쓴다.** 계산은 지금처럼 받은 인자만으로 한다(엔진 요청이 바뀌지 않는다 — 기본값을 지어내지 않는다는 규칙 그대로). 상태에는 **그 도구의 인자 묶음을 통째로**(주지 않은 것은 빈 칸으로) 쓴다 — 그래야 화면의 입력과 화면의 결과가 같은 것을 말한다. 새 도구 셋: `get_case_inputs` · `set_case_inputs` · `run_case_check`. 있는 도구의 이름 · 인자는 그대로.
6. **`.csd` 1.4** = 1.3 + `case`(상태 · 출처 · MCP 전용 인자 · 판). 1.3 모양의 `designInputs` 도 함께 쓴다 — 옛 빌드(1.3)는 1.4 를 열 수 있고(주 판 1), `case` 를 모르고 `designInputs` 로 연다.
7. **저장 안 한 변경**은 호스트가 안다: 상태 판(`rev`)과 모델 서명이 저장 · 열기 때의 것과 다르면. 보기 설정 · 단위 전환 · 결과만의 변화는 세지 않는다.
8. **독립 프로그램**: 상태가 호스트에 있으므로 다리의 「새로 고침 앞에 모으고 뒤에 되돌리기」(`inject.ts`, V5-03 · V5b-02)와 화면 없는 대역의 「마지막 연 파일의 입력」(`standin.ts`)을 걷어 낸다. 새 화면(`desktop/ui`)은 MCP 와 같은 `get_case_inputs` 로 부재 · 하중 · 접합 줄을 채운다.
9. 정할 것 7가지는 13절. 고정하며 찾은 결함 8건은 부록(설계와 별개).

## 2. 상태 모델

### 2.1 세 무리

| 무리 | 무엇 | 주인 | 저장 |
|---|---|---|---|
| **모델** | 단면(절점 · 요소 · 템플릿 · 치수), 재료 E · ν · G, 경계조건, 반파장, 종방향 항, 고유치 수, 하중 경우 · 기준응력 · custom P/M, 스프링 · 구속 · GBTcon | `StcfsdPanel._model`(지금 그대로) | `.csd` `model` |
| **검토 상태** `CaseState` | 위 밖의 모든 공학 입력 — 재료 Fy · Fu · 강종, 부재 · 설계법, 경간 · 지점 · 랩 · 간격, 하중, 데크 · 가새 · §I6.2.1, 설계 길이 · Cb · Cm, 소요강도, β · R · 냉간가공 · 비탄성 여유, 웹 크리플링, 소성 fy, 진동, 랩 · 단일 접합 — 와 MCP 에만 있는 설계 인자 | **호스트(새로)** | `.csd` `case` (+ 옛 빌드를 위한 `designInputs`) |
| **보기** | 단위 표시(US / SI), 모드 형상의 길이 · 모드, cFSM 표시 체크 5, 열린 탭 | 화면 | `.csd` `case.view`(단위 · 표시 체크만 — 지금도 저장된다) |

결과(해석 · 하중 · 설계 · 랩 · 접합)는 지금처럼 호스트의 `_last*` 가 갖는다. K2 는 결과에 「만든 입력의 판」을 붙인다(8절).

### 2.2 모양

```ts
// src/case/caseState.ts (새로 — vscode 를 쓰지 않는 순수 모듈. 확장과 독립 프로그램이 같이 쓴다)
interface CaseState {
  schema: 'stcfsd-case/1';
  rev: number;                         // 받아들인 변경마다 +1 (모델 변경은 세지 않는다 — 모델 서명이 따로)
  units: 'US';                         // 늘 US. 값의 단위는 FIELDS 의 단위 종류(아래)
  inputs: Record<FieldKey, number | string | boolean | number[] | null>;   // FIELDS 의 검토 키(모델 칸 제외)
  spans: { spans: (number|null)[]; supports: string[]; lapsPerSupport: { left: number|null; right: number|null }[] };  // ft
  sources: Record<FieldKey | 'spans' | 'supports' | 'lapsPerSupport', Source>;
  mcpOnly: Partial<Record<ToolName, Record<string, unknown>>>;   // 화면 칸이 없는 MCP 인자(목록 JSON 의 mcpOnlyDesignArgs)
  view: { unitSystem: 'US' | 'SI'; cfsm: { enable: boolean; G: boolean; D: boolean; L: boolean; O: boolean } };
}
type Source = 'default' | 'user' | 'ai' | 'file' | 'load-analysis' | 'mirror';
```

- **키는 지금의 `.csd` 키 그대로**(`fy`, `Lb`, `wcN`, `connLapLeft` …). 묶음(재료 · 부재 · 하중 · 설계 · 웹 크리플링 · 접합)은 표의 열로 둔다 — 키를 다시 짓지 않는다. 이름을 바꾸면 1.0 – 1.3 이전, `.csd` 시험, 새 화면, MCP 가 모두 따라 바뀌어야 한다.
- **거울은 한 값으로.** 지금 `.csd` 에는 같은 재료가 셋 · 둘로 들어 있다 — `fy`(③ 설계 Fy, 읽기 전용) · `fyLoad`(① Fy) · `plasticFy`(소성 fy), `fu` · `fuPre`. 상태에는 `fy` · `fu` 하나씩. 1.3 모양 `designInputs` 를 쓸 때는 셋 · 둘에 같은 값을 쓴다. 다른 값이 든 옛 파일은 지금 규칙대로 `fy` · `fu` 가 이긴다(지금은 `fuPre` 가 ① 에 남아 탭마다 달리 보인다 — 결함 D-3). 접합 Fy · Fu 는 따로 둔다(지금도 사람이 고칠 수 있다) — 출처가 `mirror` 인 동안은 재료를 따른다.
- **빈 칸 = `null`**(입력 없음 — 지어낸 값이 아니다, V4-06 · 07). 엔진 요청을 만들 때 지금의 규칙 그대로 — 필수는 막고(`reqNum`), 하중 성분은 0(`zeroNum`), 선택은 보내지 않는다(`_optNum` · `_optPos`).
- **표 하나.** `designState.FIELDS` 의 행 `[key, id, unit, kind]` 에 열을 더한다: `owner`(`model` | `case` | `view`), `group`, `default`(지금 화면의 처음 값을 US 로 — 3절의 ⚑ 를 여기 한곳으로 모은다), `invalidates`(8절). 화면 · 호스트 · `.csd` · 단위 전환 · 시험이 이 표를 쓴다(지금 단위 전환과 저장이 그러듯이). 호스트는 `require('../../webview/js/designState.js')` 로 읽는다(UMD — 이미 node 시험이 그렇게 읽는다). 새 열은 덧붙이기만 — 지금 쓰는 곳은 앞 네 열만 본다.

### 2.3 단위 — 하나, US

**정규 단위는 엔진의 US 다**: 길이 in(경간 · 간격 · 브레이스 · 경간 표의 랩은 ft), 두께 · 반지름 in, 응력 ksi, 힘 kips, 모멘트 kip-in, 면압 psf, 단면 2차 모멘트 in⁴, 회전 강성 kip-in/rad/in, 횡 강성 kip/in/in, 밀도 kip·s²/in⁴. 지금 `designState` 와 `.csd` 와 엔진이 쓰는 그것이다.

- SI 는 가장자리에서만 — 화면 표시(`app.js` 의 `UNIT` 표, 12 자리)와 MCP(`siUnits.ts`, `units: 'SI'`).
- SI 를 정규로 하지 않는 까닭: 엔진 요청이 바뀐다(모든 요청을 SI → US 로 바꿔 보내야 하고, 그 반올림이 고정한 315건의 바이트를 바꾼다). `.csd` 1.0 – 1.3 이 모두 US 다.
- **화면의 반올림이 상태로 새지 않게.** 지금은 SI 화면에서 칸 글(12 자리)을 다시 읽어 US 로 바꾸므로, 열고 저장만 해도 47 키가 최대 4.5e-11 바뀌고, `Example/test.csd` 를 SI 로 열면 E 가 29500 → 29499.99999297 ksi 가 된다(고정값 `examples`). K2 에서 화면은 **사람이 고친 칸만** 다시 읽어 보낸다. 그래도 바이트까지 같게 가기 위해 그 고침은 단계 K2-7 에서 따로 한다(그 전 단계에서는 지금의 표시 → 읽기 경로를 그대로 흉내 내 고정값을 지킨다 — 11절).

### 2.4 판

- `schema: 'stcfsd-case/1'` — 키의 뜻이 바뀌면 올린다. 키를 더하는 것은 판을 바꾸지 않는다(모르는 키는 읽을 때 버리고 경고 — `.csd` 의 모델 키처럼, V5b-01).
- `rev` — 받아들인 변경마다 +1. 지금의 `_derivedInputRevision`(입력이 실행 중에 바뀌면 결과를 버린다)을 이것으로 바꾼다(같은 뜻, 이름만).

| MCP 도구 | 받은 인자(5절의 묶음 규칙) | `ai` |

| 처음 값 | 표의 `default` | `default` |
| 결과 | 입력을 쓰지 않는다(하중 해석 채우기만 예외 — 위) | — |

### 3.2 충돌

- **호스트 하나가 차례를 정한다.** 모든 변경은 호스트를 거쳐 `rev` 를 받는다. 마지막에 쓴 것이 이긴다 — 키마다.
- **사람이 본 적 없는 값을 덮지 않는다.** 화면의 `caseEdit` 는 `baseRev`(화면이 마지막으로 받은 판)를 싣는다. 어떤 키가 `baseRev` 뒤에 다른 이(MCP · 파일)에게 바뀌었으면 그 키의 화면 변경은 받지 않고 지금 상태를 다시 보낸다. 화면은 그 칸에 「AI 가 바꿨습니다」 를 잠깐 띄운다. 다른 키는 받는다.
- **치고 있는 칸은 덮지 않는다.** 화면은 포커스가 있는 칸에 온 값을 칸을 떠날 때 얹는다(그동안 칸 옆에 새 값 표시). 그 칸의 변경은 위 규칙으로 걸러진다.
- 실행 · 저장 전에 화면은 밀린 변경을 먼저 보낸다(`caseEdit` → 답을 받은 뒤 실행). 그래서 「칸에 넣고 바로 단추」 가 지금처럼 그 값으로 돈다.

## 4. 호스트 ↔ 웹뷰

### 4.1 메시지

| 방향 | 메시지 | 뜻 | 바꾸는 것 |
|---|---|---|---|
| 호스트 → 화면 | `caseState {rev, inputs, spans, sources, view, reason, changed}` | 상태 전체(작다 — 약 130 값). 화면은 표로 칸에 얹고(지금의 `_applyValues` · `_fillSpans`), 연동을 돌린다(지금의 `_fireRestoredInputUpdates` — 결과를 지우지 않게 막은 채) | `restoreDesignInputs` |
| 화면 → 호스트 | `caseEdit {baseRev, changes: {key: value}, origin}` | 바뀐 키만. `origin`: `user` · `mirror` · `load-analysis` · `unit-toggle` | `collectDesignData` / `designDataCollected` |
| 호스트 → 화면 | `caseAck {rev, rejected: [key]}` | 받아들인 판, 받지 않은 키(3.2) | — |
| 호스트 → 화면 · 다리 | `caseDirty {dirty, rev}` | 7절 | — |
| 화면 → 호스트 | `runDesign {baseRev}` 등(K2-4 부터) | 본문 없이 「상태로 돌려라」 | 지금의 본문 있는 `runDesign` · `runPurlinDesign` · `analyzeLoads` · `runConnection` · `runLapConnection` |
| 화면 → 호스트 | `webviewReady` | 처음이면 지금처럼 기본 단면. **두 번째부터는 아무것도 새로 만들지 않고** 모델 · 상태 · 결과를 다시 보낸다 | 지금은 두 번째에도 기본 단면으로 덮는다(고정값 `reload`) |

`saveProject` · `openProject` · `invalidateDerivedResults` 는 남는다. `invalidateDerivedResults` 는 `caseEdit` 가 대신하게 되면(호스트가 키로 무효화를 안다 — 8절) 지운다.

### 4.2 화면은 어떻게 편집기가 되나 — `app.js` 를 다시 쓰지 않고

`designState.js` 에 두 함수를 더한다(순수 — node 시험이 부른다).

1. `snapshot(deps)` = 지금의 `collectDesignInputs`. 화면은 **마지막으로 호스트와 맞춘 상태**를 들고 있다.
2. `diff(last, now)` → 바뀐 키.

화면은 ① `change` · `input`(글자 칸은 300 ms 모아서) 이벤트마다 ② 호스트 메시지 처리기(`loadAnalysisComplete` 등 — 칸을 채우는 것)가 끝날 때마다 ③ 단위 전환 뒤에 `snapshot` 을 떠서 `diff` 를 보낸다. 칸을 직접 고치는 곳(거울 · 강종 · G · V4-17 · β · 하중 해석 채우기 · 단위 전환의 12 자리 다시 쓰기)이 어디에 있든 하나하나 고치지 않아도 다 잡힌다. 표는 119 키 + 경간 표라 가볍다(지금도 저장 때 같은 일을 한 번 한다).

`caseState` 를 얹은 직후에는 `last` 를 그 상태로 바꾼다 — 메아리가 생기지 않는다. 모델 칸 19개는 보내지 않는다(모델이 주인 — 지금처럼 단추로).

### 4.3 그림자 — 바이트까지 같은지 먼저 본다

K2-2 에서 호스트는 상태로 엔진 요청 본문을 만들되(`src/case/requests.ts` — `collectDesignRunPayload` · `collectLoadAnalysisPayload` · 랩 · 단일 접합 · 해석 · 템플릿을 옮긴 것) **쓰지 않고**, 화면이 보낸 본문과 비교만 한다. 시험 모드에서는 다르면 예외. 고정한 `gui-*` 흐름이 모두 같아진 뒤에 묶음마다 호스트의 본문으로 바꾼다(K2-4).

지켜야 할 것(지금 본문에서 읽은 것 — 그림자가 잡는다): 키의 차례, 보내지 않는 키(`undefined`)와 0 의 구분, 선택 칸의 `|| 'EOF'` 같은 대체, 경간 수가 `cont-N` 으로 바뀌는 것, 하중이 psf × 간격(plf) · Wu 는 음수, 랩이 안쪽 지점의 최댓값(`laps`)과 지점별(`laps_per_support`) 둘, 하중 본문의 `section` 을 화면 템플릿 칸 + 단면 성질 `Ixx` 로 만드는 것, 휨 설계가 `KxLx` · `Cmx` 까지 보내는 것, 압축이 `Tu = Pu`(같은 칸) 를 보내는 것.

**랩은 결과에 기댄다** — 본문의 `Se` · `Sf` · `Mnd` · `Vn` 은 화면의 `_lastDesignResult`(퍼린이면 화면이 고른 지배 구간 — `_pickGoverningPurlinDesign`)와 `lastProps.Sx` 에서 온다. 호스트는 퍼린 결과 전체만 갖는다. 그래서 랩 묶음은 지배 구간 고르기를 순수 모듈로 옮긴 뒤에 바꾼다(정할 것 6).

## 5. MCP

### 5.1 있는 도구 — 이름 · 인자 그대로, 동작이 이렇게 바뀐다

| 도구 | 지금 | K2 뒤 |
|---|---|---|
| `aisi_design_compression` · `_flexure` · `_combined` · `_tension` | 받은 인자로 계산, 상태 없음 | 계산은 같다(같은 엔진 요청 — `mcp-*` 의 `.engine` 은 pin). 그다음 **그 도구의 인자 묶음을 상태에 쓴다**: 부재 유형 = 그 도구, 그 도구 스키마의 인자 가운데 화면 칸이 있는 것은 받은 값 또는 빈 칸(`null`), 화면 칸이 없는 것은 `mcpOnly[도구]` 에. 출처 `ai`. 그 뒤 `caseState` |

| `get_web_crippling` · `calc_deck_stiffness` · `check_*` · `cold_work` · `flange_curling` · `get_dsm_values` | 계산기 | 그대로 — 상태에 쓰지 않는다(검토 조건이 아니라 따로 묻는 계산) |

| `save_project` · `load_project` | 원시 모델 · `.csd` 의 `model` | `load_project` 가 `.csd` 면 상태도 연다. `save_project` 는 원시 모델 그대로(K4 에서 `.csd` 로) |

**왜 「묶음을 통째로」 인가.** MCP 가 Lb 만 주고 Cb 를 주지 않았으면 그 계산은 Cb 없이 돌았다(엔진이 「Cb 미입력」 을 밝힌다). 화면에 사람이 넣어 둔 Cb 1.0 을 남기면, 화면은 「Cb 1.0 · 결과 OK」 를 같이 보이는데 그 결과는 Cb 1.0 으로 나온 것이 아니다 — 지금의 어긋남과 같은 문제가 남는다. 그리고 「설계 검토 실행」 을 누르면 결과가 바뀐다. 통째로 쓰면 화면의 입력 = 그 결과를 만든 입력이다. 사람의 이전 값은 R2(변경 기록)에서 되돌릴 수 있게 남는다. 다른 길(합치기)은 13절의 정할 것 1.

남는 틈 하나 — **화면에서 빈 칸이 될 수 없는 칸.** 지금 화면 본문은 선택 · 체크를 늘 보낸다(`wc_support || 'EOF'`, `wc_fastened`, `wc_web_config`, `wc_flange_condition`, `use_cold_work` · `use_inelastic_reserve` 의 true/false, 휨에도 `KxLx` · `Cmx` 등). MCP 의 요청에는 준 것만 있다(고정값: MCP 휨 요청 = `Fy 50 · Lb 96 · Cb 1.14 · Mu 40 · Vu 1 · wc_N 3.5 · wc_R 0.1875` 뿐, 화면 휨 요청에는 그 밖에 `use_cold_work: true` · `wc_support: "EOF"` · `KxLx` …). 그래서 MCP 뒤에 「설계 검토 실행」 을 누르면 MCP 가 준 값은 그대로 가되, 이 칸들은 화면의 값으로 더 간다. K2-5 에서 이 칸의 상태를 「주지 않음」(`null`, 출처 `ai`)으로 두고 호스트 본문이 그때는 키를 빼게 하면 같은 요청이 된다 — 다만 그 경우 화면 칸에는 「(AI: 주지 않음 — 엔진 처리)」 를 보여야 한다. 이것도 정할 것 1 에 묶었다.

## 7. 저장 안 한 변경

- 호스트가 `savedRev` · `savedModelSig` 를 연 · 저장한 순간에 적는다. **dirty = `rev ≠ savedRev` 또는 모델 서명 ≠ `savedModelSig`.**
- 세는 것: 모든 입력 변경(사람 · AI · 파생 · 하중 해석 채우기), 모델 변경(MCP 편집 포함).
- 세지 않는 것: 같은 값 다시 쓰기, 보기 설정(모드 형상 길이 · 모드 · cFSM 표시 · 탭), 단위 전환(값이 그대로라면 — 2.3 의 반올림이 새는 동안은 단위 전환 뒤의 `unit-toggle` 변경을 세지 않는다), 결과만 새로 생긴 것(결과는 다시 만들 수 있다 — 「결과는 저장하지 않았습니다」 를 따로 보일 수는 있다).
- 화면 없는 MCP 저장(독립 프로그램)도 같은 dirty 를 쓴다. 독립 창의 닫기 · 다른 파일 열기 물음(V5-12(c), S3 에서 미룬 것)이 이것을 읽는다.

## 8. 무효화 — 어떤 입력이 어떤 결과를 낡게 하나

지금의 규칙(`app.js clearStaleResults` · `designState.VIEW_ONLY_CONTROLS` · 호스트 `_invalidateAnalysisState`)을 표의 `invalidates` 열로 옮긴다. 같은 규칙을 호스트가 키로 안다 — 화면이 `invalidateDerivedResults` 를 따로 보내지 않아도 된다.

| 바뀐 것 | 지우는 것(지금 그대로) | 어디서 |
|---|---|---|
| ② 하중계산 탭의 칸(부재 유형 · 경간 · 간격 · 하중 · 데크 · 가새 · §I6.2.1 · **소요강도**) | `load`: 하중 해석 + 아래 `design` 전부 | `tab-loads` change |
| ③ · ① 탭의 검토 칸(재료 Fy · Fu · 강종 · 냉간가공, 설계법, 길이 · Cb · Cm, β, R, 비탄성 여유, 웹 크리플링, 소성 fy) | `design`: 설계 카드 · 단계 · 상호작용 · 랩 결과 · 보고서 · 검증 | `tab-design` · `tab-preprocessor` change |
| 해석 조건 9칸(하중 경우 · P/M · 경계조건 · 반파장 3 · 고유치 수) | 칸을 바꿀 때는 없음 — 「해석 실행」 때 호스트가 `analysis` | `VIEW_ONLY_CONTROLS` |
| 진동 2칸 · 보기 7칸 | 없음 | `VIEW_ONLY_CONTROLS` |
| 모델(MCP · 템플릿 · 재료 · 절점 · 스프링 …) | `analysis` 또는 `model`(하중까지) | `_invalidateAnalysisState` |

## 10. VS Code 확장은 그대로인가

- 화면 · 칸 · 단추 · 탭이 같다. 바뀌는 것은 화면과 호스트 사이의 메시지뿐이다. `retainContextWhenHidden` 그대로.
- 같은 조작이면 같은 엔진 요청 — `gui-*` 고정값(엔진 요청 · 보인 결과)이 pin 이다. 단계마다 확인한다.
- `.csd` 1.0 – 1.3 이 열리고(고정값 `examples` · `csd-*`), 1.4 는 옛 확장도 연다(6절).
- 좋아지는 것(사용자에게 보이는): MCP 가 정한 설계 조건이 칸에 보이고 단추를 눌러도 지워지지 않는다. 「Developer: Reload Webviews」 같은 웹뷰 다시 싣기가 모델을 기본 단면으로 덮지 않는다(고정값 `reload` — 코드로 본 동작이고 VS Code 안에서는 확인하지 못했다).
- 확장의 시험: `design_state_roundtrip` · `design_state_v13_contract` · `panel_host_contract` 가 `collectDesignData` · `restoreDesignInputs` 를 글자로 찾는다(9곳) — 그 메시지를 지우는 단계(K2-7)에서 시험을 함께 고친다. 그 전까지는 두 길이 같이 있다.
