## 3. 단계별 기록

### E — 엔진(끝, 2026-11-25)

**E-1 가정한 길이로 낸 판정.** 원인 둘: ① 믿지 못하는 검토가 `verdict_from(trusted=False)` 를 지나는데 그 함수는 판정비가 1 을 넘으면 `fail` 을 냈다 — E2 · E3 · F2 · F3 자체가 아무도 정하지 않은 길이로 불합격했다(Pu = 8 에서 E2/E3 「fail 3.44」 · 전체 NG). ② 요약 항목(`E axial compression` · `F flexure`)과 H1.2 · H1.1-2 가 판정비에서 곧바로 `pass` 를 냈다(H1.2 는 「평가하지 못함」 목록을 보지도 않았다). 고침: `strength_check(..., assumed_length=True)` 는 늘 `not_evaluated`(수는 `reference` 아래). 요약 항목은 참고값 — 길이와 상관없는 검토(Pu > 설계 Pnd, F4 가 평가됐으면 Mu > 설계 Mnd)가 넘을 때만 불합격. H1.2 · H1.1-2 는 Pa · Max · B1 이 가정한 길이에서 왔으면 「평가하지 못함」, 길이와 상관없는 하한(B1 = 1 의 P/Pnd + Mx/Mnd + My/May)이 1 을 넘을 때만 불합격. H2 · H3(길이와 무관한 Mnfo), 랩 구간의 Lb = 0 · 정모멘트 구간의 「완전 지지 가정」(가장 유리한 쪽이라 불합격이 진짜다), 퍼린 사슬(하중 해석이 길이를 준다)은 그대로.

**E-2 랩 패스너의 힘 분배(R2).** 새 입력 `lap_force_model_confirmed`(불, 없으면 거짓). 모델 A 의 수는 늘 낸다. 밝히지 않았으면 `lap.fastener_group` · `lap.fastener_count` 는 `not_evaluated` — 모델 A 로도 넘거나 들어가지 않으면 불합격(그 까닭을 적는다). 블록 전단(J6.3)은 전체 전달력으로 보므로 그대로. 퍼린 사슬 · `check_lap_length` 는 이 힘을 쓰지 않는다.

**E-3 하중조합의 기준(R4).** 새 입력 `load_combination_standard` — `asce7_10`(없을 때 — 결과가 지금과 같다) · `asce7_22` · `kds_41_12_00`. 모르는 값은 허용 목록과 함께 오류. **`asce7_16` 은 넣지 않았다** — 2.3.1 · 2.3.6 · 2.4.1 · 2.4.5 의 표를 1차 자료로 확인하지 못했다(그 값을 주면 「확인되지 않아 없다」 는 오류). 출처: ASCE 7-22 는 `asce7-loads-design` 스킬의 2장(2.3.1 의 1a–5a · 2.3.6 의 6–7 · 2.4.1 의 1a–7a · 2.4.5 의 8–10)과 C7.2(적설 계수 1.6 → 1.0), KDS 41 12 00:2022 는 `kds-structural-design` 스킬의 1.7.1(식 1.7-1 – 1.7-7) · 1.7.2(1.7-8 – 1.7-15) · 5.1.3(0.65W)을 원문 PDF 13 – 14쪽 그림과 맞대 봄. 입력한 하중이 그 기준의 정의를 따라야 한다는 고지를 낸다(7-22 의 S 는 7장의 위험도 기반 적설, KDS 의 W 는 5장의 강도 수준 풍하중). **cFSM 구속.** 설계용 서명곡선은 언제나 구속하지 않은 풀이다 — `_signatureDsm` 이 모델의 사본에서 `GBTcon` 을 빼고, 준비된 값의 서명에서도 뺐다(`set_gbtcon` 은 보기만 바꾸는 일). 구속된 지금 해석은 설계의 대신 값으로 쓰지 않는다. 구속이 켜져 있으면 결과가 가정 `host.design.dsm_unconstrained` 를 적는다. 검증의 사례: Mcrd 92.03(Mcrl 없음) → Mcrl 88.3696 · Mcrd 85.7048(구속 없는 값과 같다).

**준비 실패.** 실패하면 `dsm_warning` 이 늘 까닭을 적고, 지금 해석이 빈자리를 채웠으면 `buckling_values.source` 는 `analysis-fallback`(그 해석의 길이 · 경계조건의 값임을 적는다).

**자동 준비의 Fy.** 화면이 붙은 뒤의 `prepareDesignDsm` 은 검토 상태의 설계 Fy 로(49.99999999993936 이 아니라 50) — 한 번만 풀고 다음 검토가 그 값을 쓴다.

**저장된 좌굴값.** 지금 것일 때만 쓰고 서명의 sha256 을 같이 적는다(`preparedDesignDsm.design_signature` — 결과 봉인 안). 열 때 그 서명이 연 모델 · 설계 Fy 의 것과 같을 때만 되살린다. 서명이 없는 옛 파일의 값은 되살리지 않는다(앞 빌드의 값은 구속이 들었을 수 있다 — 다음 검토에서 다시 준비한다).

**퍼린 결과.** 같은 인자의 `analyze_loads` 가 앞의 퍼린 결과를 지우던 것 — 두 요청의 Fy · Fu 자리가 달랐다(퍼린은 맨 위, 하중 해석은 `section` 안). 견주기 전에 채운다.

**엔진 2차를 읽는 곳.** 길이와 상관없이 불합격인 결과의 판정비 · 지배 항목은 `length_independent_bound`(조합은 `interaction_length_bound`)에서 — 실행 요약 · 색인 · 점검 · 계산서 · 끼운 화면의 눈금. MCP 요약에 `utilization_note`.

**고정값.** k2 여섯 파일의 여덟 줄 — 일곱은 설계 준비의 본문에서 `GBTcon` 이 빠진 것(값은 그대로), 하나는 자동 준비의 Fy(42.78613263041172). k3 는 그대로. 새 시험 `design_chain_verify_contract.js`.

### D3 — 데스크톱: 2차를 따라가기(끝, 커밋 `a6ef020`)

길이와 상관없이 불합격이면 NG + 그 하한의 판정비와 한계상태(「하한 · 국부좌굴」), 가정한 길이의 수는 「참고」(u06c — Pu 400 kN · KtLt 빈 칸: 하한 2.82 가 NG, 5.11 이 참고). 넘지 않는 빈 길이는 그대로 「판정 없음」. `buckling_values.source` 의 글(`analysis-fallback` 등 — 함수 단위로만 시험, 준비 실패는 정직하게 만들 수 없다), 「좌굴 값의 출처」 줄의 「준비 실패」. cFSM 구속을 켰을 때의 가정이 정보 창 · 모델 › 가정에 뜬다(r43).

## 4. 남은 것

**사용자가 볼 것.**

- 1절의 결정 R1 – R11 은 오케스트레이터가 권고값으로 정한 것이다 — 뒤집으면 고칠 곳이 있다(특히 R2 랩 패스너의 판정 규칙, R4 의 처음 값이 ASCE 7-10 인 것, R1 의 「언제나 FSM」).
- **이 빌드부터 저장해 둔 결과는 「다른 엔진」 으로 버려진다**(엔진이 바뀌었다). 열면 띠가 뜨고 [다시 계산] 이 좌굴 해석 → 부재 검토 → 랩을 되살린다. 준비된 설계용 좌굴값도 옛 파일의 것은 되살리지 않는다.
- 랩 접합은 「패스너가 힘을 고르게 나눈다는 가정으로 판정한다」 를 밝히기 전에는 패스너 군 · 수 항목이 「평가하지 못함」 이다 — 랩의 종합 판정이 「판정 없음」 으로 나온다(그 가정으로도 넘으면 NG).
- 푸시하지 않았다(작업 브랜치 `feature/desktop-program` 에 커밋만).

**하지 않은 것.**

- ASCE 7-16 의 하중조합 — 표를 1차 자료로 확인하지 못했다(넣으려면 2.3.1 · 2.3.6 · 2.4.1 · 2.4.5 의 원문).
- 새 검토 조항(R4e · 6묶음): 거트 · 스터드의 약축 · 축력, 처짐 한계, I6.4.1 정착력, 햇 휨의 횡좌굴, 구멍, H4, B2, 전단 보강재, 보-기둥의 증폭 모멘트 — 지금처럼 결과에 「평가하지 못함」 · 범위 고지로 밝힌다.
- 화면 칸이 없는 인자(`kphi` · `Fcre` · `moment_sign` …)는 그 호출에만(R5f).
- 시그마 단면 예시(원 도면), 코드 서명, 앱 아이콘, 진짜 VS Code 안의 확장 시험, 알림 문구를 사람이 읽는 일.

**알고 남긴 것.**

- 원형관 압축의 길이와 상관없는 하한은 항복만 본다. 지진 고지의 ASCE 7-10 · KDS 쪽 글은 일반적인 말이다.
- 엔진이 반올림 전 값을 주지 않는 것: `Fy_used` · `Fy_original`(295 MPa 가 295.02 로 돌아올 수 있다), `Fcre_detail` 의 길이 · 재료, 수의 배열.
- `aisi_design_*` 가 Mux · Pu · Vu 를 쓰면 하중 해석이 낡음이 된다 — 화면에서 그 칸을 고칠 때와 같은 규칙이지만 MCP 에서는 새 동작이다.
- 점검(`validate_design`)의 반파장 항목(개수 · 최대 ≥ 비지지 길이)은 여전히 보기용 격자를 본다.
- 「해석식 좌굴값」 표시와 `analysis-fallback` 의 글은 준비가 실패해야 뜬다 — 정직하게 만들 수 없어 함수 단위로만 시험했다. 끼운 화면의 새 보기(랩 고지 · -M 머리 · SI 카드)는 진짜 창에서 눈으로 보지 않았다.
- 화면 값과 호스트 값을 맞대는 검사(R11): 12번째 자리의 1 은 그 값이 다른 단위의 눈금에 우연히 앉으면 지나갈 수 있다(11번째 자리부터는 늘 걸린다).
- 퍼린 38구간 요약의 크기는 시험의 기준(40 KB)까지 여유가 거의 없다(그대로).
- 독립 검증은 진짜 웹뷰와 둥근 모서리 단면에서의 격자 정확도를 보지 못했다.
