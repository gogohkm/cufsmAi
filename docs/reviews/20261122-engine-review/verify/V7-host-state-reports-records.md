**설계 §3.5 「사람만」 의 층 — 이 코드에서 진짜인 것.** 층 1 – 6(MCP 에 이름 없음 · 다리 안에서만 건넴 · 맨 위 틀의 열쇠 · 사람의 입력 · 화면이 본 지문 대조 · `AsyncLocalStorage` 거절)은 **코드에 없다** — `RecordsDesk` · `person` · `AsyncLocalStorage` · `/api/person` 이 0 건이고, `src/` 어디도 `records` 를 부르지 않는다. 모두 아직 약속이다. 층 7(서명)은 있지만 일반적이다: `index` 가 내보내는 `writer.loadOrCreateWriter(keyDir)` 는 `sign()` 을 가진 객체를 주고, `RecordLog.append` 는 아무 spec · 아무 `actor.kind` 나 받는다(`p_person.js`: 호출하는 쪽이 지어낸 `reviews` spec 에 `actor:'person'` → `status ok, countable true`). 그래서 서명은 「이 PC 의 프로그램이 썼다」 만 증명하고 AI 길인지 사람 길인지는 가리지 못한다 — 장래 MCP 도구가 이 모듈에 닿으면 「사람만」 은 그 도구의 코드에만 기댄다.

**같은 사용자 권한으로 할 수 있는 것 · 없는 것(솔직하게).** 열쇠 파일의 ACL 은 상속(SYSTEM · Administrators · 사용자 모두 F)이고 mode 0600 은 Windows 에서 무시된다 → **같은 사용자의 모든 프로세스**(Claude Code 의 셸, 홈을 연결한 파일 MCP, 내려받은 스크립트)가 `writer.key` 를 읽어 셀 수 있는 「사람」 표시를 지어낼 수 있다. `trust.json` 에 `by:'self'` 를 더하거나 열쇠를 바꿔 넣는 것도 같다 — 바꾼 열쇠는 처음 열 때 자동으로 self 로 믿어지고 옛 줄도 계속 검증된다. **막는 것**: 프로젝트 폴더에만 쓸 수 있는 쪽(동기화 폴더의 동료, 폴더만 연결된 AI)이 셀 수 있는 줄을 지어내는 것 — 꾸민 카드 · 남의 열쇠 · 다른 프로젝트 id · 줄 바꿔치기는 모두 unverified / untrusted. **그쪽이 여전히 할 수 있는 것**: V7-20 · 22 · 23 · 26 · 29 · 30(무력화 · 접기 오염 · 동료 기록 되감기). 설계 §3.5 의 「위협 모델 밖」 문장은 이 범위에서만 맞다 — 문서에 「같은 사용자 권한의 프로세스는 사람 표시를 지어낼 수 있다(DPAPI · 하드웨어 열쇠 전까지)」 를 적어야 한다.
