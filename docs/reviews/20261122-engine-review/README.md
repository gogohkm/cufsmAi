## 방법

1. 맡은 파일을 **끝까지** 읽는다. 표본으로 보지 않는다. 보고서 끝에 읽은 파일과 줄 수를 적는다.
2. 1차 근거와 대조한다. 계수 · 한계 · φ/Ω 를 기억으로 판정하지 않는다.
   - AISI S100-16: Skill 도구로 `aisi-cold-formed-steel` 을 읽는다(안 되면 `C:\Users\USER\.claude\skills\aisi-cold-formed-steel\` 의 `SKILL.md` → `references/` · `data/` 를 직접 읽는다). 설계 매뉴얼 예제는 저장소의 `Example/*.md` 에도 있다.
   - FSM 이식부: `Ref_Source/` 의 MATLAB 원본.
3. 수치로 가를 수 있는 의심은 수치로 가른다. 닫힌 해, 손계산, AISI 매뉴얼 예제값, 대칭 · 극한 경우와 비교한다.
   - 실행: `C:\Coding_Works\cufsmAi\.venv\Scripts\python.exe <스크립트>` — 스크립트 첫머리에 `sys.path.insert(0, r'C:\Coding_Works\cufsmAi\python')`
   - 엔진 내부 단위는 US(in, kip, ksi)다. SI 변환은 경계(MCP · 화면)에서 한다.
4. 찾을 것
   - 틀린 식 · 계수 · 한계값, 틀린 분기 조건, 조항 적용 범위를 확인하지 않는 것
   - 단위 실수, 부호 규약 실수
   - **비보수적인 조용한 대체**: 빠진 입력을 기본값으로 채움, `except: pass`, 값이 0 이라 한계상태를 건너뜀, 검출 실패를 "감소 없음"으로 처리
   - ASD / LRFD / LSD 계수 실수
   - 이식 오류: 인덱스(1 → 0 기준), 배열 모양, 전치, 정렬, 복소 고유값 처리
   - 수치 견고성: 나쁜 조건수, 허용오차, 0 나눗셈, 빈 배열
   - 같은 계산의 중복 구현이 서로 다른 것, 호출 경로에 따라 결과가 달라지는 것
   - 검사처럼 보이지만 실행되지 않는 코드
5. 확인한 것과 의심만 하는 것을 구분한다.

## 보고서 형식 (한국어)

```
# R<n> — <영역>

## 요약
(발견사항 수: P0 n · P1 n · P2 n · P3 n. 한두 문단)

## 발견사항

### R<n>-01 [P0|P1|P2|P3] [확인|의심] 제목
- 위치: `경로:줄`
- 현상: 무엇이 틀렸나
- 근거: 조항 번호와 식 / MATLAB 원본 `경로:줄` / 수치 재현(스크립트 경로와 숫자)
- 영향: 어느 출력이, 안전측인지 비안전측인지, 크기를 알면 크기
- 수정안: 구체적인 변경
- 회귀 시험: 입력 → 기대값

## 맞다고 확인한 것
(짧게. 건너뛴 것이 아니라 본 것임을 다음 사람이 알 수 있게)

## 확인하지 못한 것
(까닭과 함께)

## 읽은 파일
```

심각도: **P0** 보통의 사용에서 잘못된 합격 / 불합격 판정 또는 비보수적 강도 · **P1** 특정 조건에서 강도 · 판정이 틀림 · **P2** 정확도 · 완성도 · 견고성 · **P3** 유지보수 · 표기.

확신: **확인** = 수치 재현 또는 원문 대조로 확정 · **의심** = 근거는 있으나 확정하지 못함.
