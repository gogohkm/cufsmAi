# StCFSD 전체 코드·UI 감사 및 수정 결과

**프로젝트:** StCFSD (Cold-Formed Steel Section Designer)

**감사일:** 2026-07-20

**감사자:** Codex

**설계 기준 범위:** 프로젝트가 대상으로 삼는 AISI S100-16 및 포함 설계 예제

## 1. 이번 감사의 목적과 범위

여러 차례 누적된 수정 뒤의 회귀 결함을 찾기 위해 특정 파일만 재확인하지 않고 다음 경로를 함께 추적했다.

- Python FSM/cFSM 해석, DSM 분류, AISI 강도·상호작용·하중·퍼린 설계
- TypeScript 확장 호스트, Python JSON-RPC 브리지, MCP 도구 스키마
- WebView HTML, 입력 단위 변환, 상태 저장·복원, 결과 렌더링
- WebView↔Extension 메시지와 DOM id 계약
- 프로젝트 저장 파일의 해석·설계 결과 유효성
- Python/TypeScript/JavaScript 정적 검사, Python 회귀시험, VS Code WebView 통합시험, 프로덕션 빌드

이번 문서는 2026-04-10판의 “추가 오류 없음”, “핵심 공식 모두 정확”, “실무 사용 적합” 같은 포괄적 결론을 폐기하고, 이번에 실제 확인한 범위·수정·잔여 한계를 기록한다.

## 2. 확인 후 수정한 사항

| ID | 영역 | 발견 내용 | 반영 내용 |
|---|---|---|---|
| A-01 | DSM 데이터 흐름 | 하나의 현재 FSM 곡선을 보고서·검증·저장에서 압축 `P`와 휨 `Mxx` 모두로 환산 | 현재 응력의 하중 계열과 일치하는 DSM만 추출하는 공통 함수로 통합하고, 별도 준비 DSM은 `prepared_design_dsm`으로 구분 |

| A-19 | Python 품질 | 전체 Ruff에 레거시 세미콜론, 미사용 import/변수, bare except 등 160건이 잔존 | 공개 재수출은 `__all__`로 명시하고 나머지 경고를 동작 보존형으로 정리하여 전체 Ruff 0건 달성 |

| A-22 | 3D 의존성 | 선 그리기 하나를 위해 전체 `MeshBuilder`와 범용 StandardMaterial 셰이더군을 포함 | `CreateLines` 직접 import 및 정점색 전용 경량 셰이더로 교체; 모드 형상 색상·양면 렌더링 유지 |

이번 감사 이전에 같은 작업 묶음에서 함께 반영된 구조 안전성 수정도 재검증했다. 여기에는 비양수 고유치/좌굴강도 진단, cFSM 분류의 DSM 전달, 압축·휨 전체좌굴 입력 검증, 상호작용식의 0 강도 실패 처리, Cmx/Cmy 보수 기본값, 약축 강도 명시 요구, 해석 실패 진단 전달이 포함된다.

## 3. AISI 예제 대조 결과

이번 대조에는 `aisi-cold-formed-steel` 스킬의 AISI S100-16 설계 예제 색인과 Example II-1 계열을 사용했다.

| 항목 | 대조 결과 |
|---|---|
| Example II-1B DSM 휨 | My 125.95≈126.0, Mnl 93.599≈93.6, Mnd 99.900≈99.9, LRFD 강도 84.239≈84.2 |
| Example II-1A 웹크리플링 | EOF 2.565≈2.56, IOF 4.245≈4.24 등 회귀 통과 |
| Example II-1C 데크 횡강성 | t1=0.0179, t2=0.059, s=12 in에서 kx=1.280 kip/in/in으로 문서값 1.28과 일치 |
| Example II-1C 데크 회전강성 | 현재 자동식 0.194, 문서 예제값 0.113. 자동값은 정밀 재현식으로 간주하지 않고 예비 근사치로 표시하며 시험값 override 경로 제공 |

중요: AISI 예제도 데크 횡·회전 구속 강성을 프로젝트별 시험자료로 정하는 절차를 전제로 한다. 따라서 두 자동값 모두 최종 설계용 시험값을 대신한다고 문서화하지 않았다.

## 5. 잔여 한계와 개선 우선순위

다음은 이번에 숨기거나 임의 공식으로 메우지 않은 잔여 한계다.

1. 데크 `kphi`와 `kx` 자동값은 예비설계 근사치다. 프로젝트별 패널·체결부 시험값을 우선 사용해야 한다.
2. Angle/Hat/Tee 등 비 C/Z 단면의 자동 §F2.1.2 전체좌굴은 일반화되지 않았다. 해당 경로는 명시적 `Fcre`/가용강도 입력이 필요하다.
3. cFSM 분류가 실패하거나 모드형상이 없으면 DSM은 명시적으로 휴리스틱 분류에 폴백한다. 특수 단면·복합 모드에서는 곡선과 모드형상을 엔지니어가 확인해야 한다.
4. Hat unfastened ETF/ITF, built-up/nested 다중 웹, 일부 edge-distance 자동 추론은 기존 구현 범위 밖이다.
5. 소성 상호작용 UI는 현재 P-M11 및 P-M22의 정규화된 2D 주축 다이어그램이다. `PlasticSurfaceRenderer.ts`는 향후 별도 3D 캔버스·내보내기 경로를 위한 프로토타입으로 남아 있으나, 현재 UI에서 호출되지 않으므로 프로덕션 초기 번들에서는 제외했다.
6. UI 검사는 DOM·메시지·단위·상태 계약과 실제 VS Code 통합 실행을 포함하지만, 모든 OS/테마/DPI 조합의 픽셀 단위 시각 회귀시험은 포함하지 않는다.

## 6. 결론

이번 감사에서 확인된 고위험 누적 결함은 코드에 반영했다. 특히 잘못된 하중 계열의 DSM 재사용, 양력 곡선 선택, 비동기 stale 결과, 실시간 모델 덮어쓰기, UI 파생결과 재사용 문제를 차단했다.

현재 상태는 포함된 회귀시험과 AISI 예제 범위에서 일관된다. 다만 “모든 단면·모든 설계 조항에 대해 검증 완료” 또는 “추가 엔지니어 검토 없이 최종 설계 사용 가능”으로 확대 해석해서는 안 된다. 위 잔여 한계가 적용되는 프로젝트에서는 시험 강성, 명시적 전체좌굴 강도, 모드형상 검토가 필요하다.

후속 품질 정리에서 전체 Ruff 160건을 0건으로 줄였고, 3D 렌더러의 초기 로딩과 자원 누수를 개선했다. 이 변경 뒤에도 Python 72개 회귀시험, TypeScript, ESLint, WebView 계약시험 및 프로덕션 빌드는 모두 통과했다.
